## خطوات التنفيذ التالية
1. G1: إنشاء بيانات اختبار محددة لشركة ثانية وملفات خاصة، واختبار HTTP لجلسات مخولة وغير مخولة، ومنع القراءة/الكتابة/توقيع رابط عبر الشركات. لا يعادل اختبار SQL اختبار HTTP. توثيق التنظيف والنتائج.
2. سياق الأدوار: واجهة خادم تعيد أدوار وصلاحيات المستخدم الموثق وعضوياته الفعالة، دون استنتاج الدور من البريد أو user_metadata. تغطي تعدد العضويات وتعطيل العضوية/الشركة. لا نفترض إمكانية قراءة الموظف لـmembership_roles عبر السياسة الحالية.
3. ربط أول رحلة شركة حقيقية: عضوية → لوحة الدور → الموظفون والدعوات → إعدادات الاسم، ثم نطاق مدير الفرع وبوابة الموظف. لا تستخدم أرقام المعاينات كبيانات فعلية.
4. إدارة المنصة SA: دور معتمد في المواصفات، لكن حسابه ومسار صلاحياته لم يجهزا. تحديد نموذج صلاحيات مستقل عن عضوية الشركة، واختبار منع CO/BM/EM من /admin/dashboard والطلبات الإدارية. تعيين بريد مسؤول المنصة قبل تفعيل صلاحياته؛ لا ترقية تلقائية لحساب سعود الحالي.
5. Q/Human Gate: فحص RTL والجوال والحالات والرحلة والصلاحيات، ثم اعتماد الشريحة. لا دمج أو إطلاق إنتاج قبل اجتياز البوابة.
