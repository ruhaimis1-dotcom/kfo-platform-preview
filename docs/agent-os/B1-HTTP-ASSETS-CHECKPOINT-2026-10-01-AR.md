# كفو — جولة تفعيل سياق الأدوار وتجهيز فحص الملفات

## استعادة الاتصال — متابعة 1 أكتوبر

بعد إبلاغ المستخدم بإعادة الربط، نجحت قراءة SQL في مشروع كفو الصحيح. أكدت وجود RPC وبقاء العضويات الثلاث نشطة وصفر بيانات معاملات الاختبار. أعيد تجهيز B بالملف نفسه داخل BEGIN/ROLLBACK ونجحت العملية؛ قراءة لاحقة أكدت عدم بقاء B أو مستخدمي/شركات الاختبار، وبقاء العضويات الأصلية الثلاث نشطة وصفر ملفات Storage.

قراءة سياق الأدوار للحسابات الأصلية نجحت عبر SQL مع محاكاة هوية authenticated داخل معاملة متراجعة: CO على الشركة، BM على الفرع المعتمد، EM دون صلاحيات إدارة. هذه ليست جلسات HTTP موثقة. عائق صلاحية اتصال SQL المذكور أدناه أصبح محلولًا.

الواجهة وفحوص الأدوار/الملفات جاهزة عند commit 242e376 على الفرع المحلي `agent-os/kfo-b1-role-context-20261001`؛ لم يحدث push أو نشر. الخطوة الحالية: اعتماد رفع معاينة الاختبار المحدثة ثم تشغيل HTTP للحسابات وتجهيز B الحية المؤقتة قبل رفع الملفين. G1 ما زالت مفتوحة. PR #18 القديم Draft على فرع المعاينة السابق، ولم يعدّل في هذه المتابعة.

## المنجز

- تطبيق RPC `my_access_context` في مشروع كفو `ktkdcfxeaicbykdurlfg`؛ سجل الترحيل الفعلي `20261001090607`. ملف الترحيل أنشئ عبر CLI ثم طابق اسمُه الإصدارَ الذي أعاده سجل MCP. لا يمنح SA ولا يغير عضويات الحسابات.
- اختبار SQL بعد التطبيق نجح داخل معاملة تراجعت بالكامل: CO/BM لشركتين، دور الموظف مع منع قراءة جدول الأدوار مباشرة، بيانات مستخدم مزورة، تعطيل العضوية والشركة، منع المجهول والجلسة دون هوية.
- فحص HTTP حي للمجهول نجح: **401 / 42501**. هذا لا يثبت نجاح الجلسات المسجلة.
- ربط سياق الأدوار بصفحة العضويات محليًا. تستخدم هوية موثقة وتطابق الشركة والعضوية وتستبعد نتيجة جلسة تغيرت. تعرض دورًا ونطاقًا فعليين؛ لا تفتح لوحات المعاينات كأنها وظائف تشغيلية.
- إضافة فحص HTTP مستقل للأدوار: هوية الجلسة، منع المجهول، دور العضوية ونطاقه، عدم توسيع صلاحيات الموظف، إعدادات الشركة، ومطابقة السياق مع عضويات المستخدم.
- تجهيز فحص Storage للحسابين: رفع ملف خاص محدد دون استبدال، تنزيل البايتات ومطابقة علامة الاختبار، إنشاء رابط مؤقت وتنزيله، منع القراءة والتوقيع والكتابة بين الشركتين، وتنظيف الملف المحدد بعد مطابقة محتواه. لا تظهر رموز الجلسات أو الروابط المؤقتة في النتائج.
- البناء و**40/40** اختبارًا محليًا نجحت؛ اختبارات HTTP/Storage المحلية محاكاة، ولا تعادل فحصًا حيًا.

## حدود الفحص والعائق

استُدعي تجهيز شركة B داخل معاملة تنتهي بـROLLBACK، لكن أداة Supabase رفضت تنفيذ الطلب برسالة `You do not have permission to perform this action`. رفضت أيضًا قراءة التحقق اللاحقة. لذلك لم تنفذ جولة تجهيز B، ولا نملك قراءة أخيرة تؤكد حالة البيانات بعد فقدان الصلاحية. آخر نجاح SQL كان اختبار RPC بعد التطبيق داخل معاملة متراجعة.

الواجهة الجديدة وأزرار الفحص محلية فقط؛ لم تُرفع أو تُدمج أو تُنشر. محاولة فتح الخادم المحلي في المتصفح رُفضت بـ`ERR_BLOCKED_BY_CLIENT`؛ ليست نتيجة فحص بصري. فحص الجوال وRTL المرئي والجلسات المسجلة والملفات الحية ما زال مفتوحًا. G1 لم تُغلق.

سياسة الملفات الحالية تتلقى نطاق الشركة فقط، بينما BM يحتاج نطاق الفرع عند فحص الصلاحية؛ لذلك فحص ملف شركة عام لا يثبت إمكانية BM قراءة ملفات فرعه. لم نُضعف السياسة لتجاوز ذلك؛ تصميم نطاق ملفات الفرع واختباره مستقلان.

## ترتيب التشغيل التالي

1. استعادة صلاحية اتصال Supabase على مشروع **kfo** المحدد، ثم قراءة RPC/سجل الترحيل والعضويات الأصلية وإثبات عدم بقاء بيانات المعاملات الاختبارية.
2. مراجعة تحديث الواجهة ثم رفع معاينة الاختبار وفق اعتماد الإصدار؛ لا نشر إنتاج تلقائي.
3. فحص دور CO ثم BM ثم EM عبر زر فحص الأدوار، من جلسات موثقة.
4. تجهيز B عبر `supabase/tests/private_asset_fixture_setup.sql`: الملف يملك ROLLBACK للتدريب. عند التشغيل الحي المقصود فقط تتحول نهايته إلى COMMIT. يضيف شركة QA-B محجوزة ودور CO لموظف الاختبار **داخل B فقط**، ويترك دوره EM داخل A. لا ينشئ مستخدم Auth أو يرقّي إدارة المنصة.
5. من سعود/CO في A، تحضير ملف A؛ من رحيمي/EM في A وCO في B المؤقتة، تحضير ملف B. يجب توثيق نجاح قراءة البايتات والرابط المؤقت **للملفين** قبل اعتبار رفض الوصول المتبادل دليل عزل.
6. إجراء فحص العزل من الحسابين ثم تنظيف الملفين عبر API. إذا نجحت كتابة أجنبية خلاف المتوقع، يتوقف الفحص ويعرض مسار probe المحدد؛ ينظفه مالك الشركة المستهدفة فقط. بعد التحقق من خلو الملفات، تعطيل الشركة B وعضويتها التجريبية مع حفظ التدقيق. لا حذف مباشر لملفات Storage عبر SQL.
7. اختبار HTTP لعزل بيانات الشركات ومتابعة أول لوحة فعلية والصلاحيات المستقلة لإدارة المنصة، ثم فحص الجوال وHuman Gate.

المطلوب لاستئناف الفحص الحي الآن: صلاحية الاتصال بكفو. لا حاجة لكلمة مرور أو رمز جلسة في المحادثة.
